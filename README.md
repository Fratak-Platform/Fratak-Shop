# Fratak Shop

فروشگاه اینترنتی فارسی (RTL) با **ASP.NET Core 10 Razor Pages**، **EF Core 10 / SQL Server** و معماری سه‌لایه.

## معماری

```
src/
├── Fratak-Shop.Data   → لایه داده: Entity ها، Configuration ها، DbContext، Migration ها، Seeder داده مرجع (استان/شهر)
├── Fratak-Shop.Core   → لایه سرویس: DTO ها، Mapper ها، سرویس‌ها (قوانین کسب‌وکار، اعتبارسنجی، OperationResult)
└── Fratak-Shop.Web    → لایه وب: Razor Pages فروشگاه، سرویس‌های نمایشی، ViewComponent ها، استایل و اسکریپت
```

| لایه | وابستگی | مسئولیت |
|------|---------|---------|
| Web  | Core, Data | صفحات، احراز هویت با کوکی، سبد خرید مهمان، سئو، درگاه پرداخت |
| Core | Data | منطق کسب‌وکار؛ صفحات هرگز مستقیم به DbContext دسترسی ندارند |
| Data | — | مدل داده و دیتابیس |

### لایه وب (`Fratak-Shop.Web`)

| مسیر | توضیح |
|------|-------|
| `Infrastructure/` | `SiteContext` (تنظیمات دیتابیسی هر درخواست)، `Auth/` (JWT + Refresh Token)، میان‌افزارهای امنیتی/URL کانونیکال/ریدایرکت سئو، Rate Limiting، sitemap و robots، سرویس پس‌زمینه انقضای سفارش‌ها |
| `Services/` | سبد خرید (کاربر/مهمان با کوکی + ادغام پس از ورود)، ورود/خروج (JWT)، لیست مقایسه، متادیتای سئو و JSON-LD، کد یک‌بارمصرف و پیامک، درگاه زرین‌پال |
| `ViewComponents/` | هدر سایت (مگامنو دسته‌بندی‌ها با کش، مینی‌سبد، منوی حساب) |
| `Helpers/` | قالب‌بندی قیمت و تاریخ شمسی، برچسب‌های وضعیت، آدرس تصاویر، مجموعه آیکون‌های قالب |
| `Pages/` | صفحات فروشگاه و ناحیه کاربری (`Pages/Profile`) و پرداخت (`Pages/Payment`) |

## صفحات و مسیرها

| `/compare` | مقایسه تا ۴ محصول |
| `/cart` ، `/checkout` | سبد خرید و تکمیل سفارش (آدرس، روش ارسال و هزینه بر اساس استان، روز/بازه تحویل، پرداخت اینترنتی/کیف پول/در محل) |
| `/payment/*` ، `/checkout/success/{no}` ، `/checkout/failed/{no}` | پرداخت و نتیجه سفارش |
| `/login` ، `/login/code` ، `/login/2fa` ، `/register` ، `/verify` ، `/welcome` | ورود با رمز عبور یا کد پیامکی (بدون رمز)، تایید دومرحله‌ای اختیاری، ثبت‌نام و تایید شماره موبایل |
| `/profile` ، `/profile/orders` ، `/profile/orders/{no}` ، `/profile/orders/{no}/invoice` ، `/profile/addresses` ، `/profile/favorites` ، `/profile/messages` ، `/profile/notifications` ، `/profile/info` ، `/profile/password` ، `/profile/wallet` ، `/profile/sessions` | ناحیه کاربری (فاکتور + PDF سمت مرورگر، اعلان‌ها، کیف پول، تاریخ تولد شمسی، تایید دومرحله‌ای، دستگاه‌های فعال) |
| `/club` | باشگاه مشتریان: امتیاز، سطح، تبدیل امتیاز به اعتبار/کد تخفیف، کد معرف، کدهای تخفیف قابل استفاده |
| `/track-order` | پیگیری سفارش بدون ورود با شماره سفارش + موبایل |
| `/blog` ، `/blog/category/{slug}` ، `/blog/{slug}` | وبلاگ |
| `/faq` ، `/page/{slug}` ، `/contact-us` ، `/coming-soon` | صفحات محتوایی پویا (درباره ما، قوانین، حریم خصوصی، ... از جدول `ContentPages`؛ آدرس‌های قدیمی با 301 منتقل می‌شوند) |
| `/sitemap.xml` ، `/robots.txt` ، `/manifest.webmanifest` | تولید خودکار از دیتابیس |

## اجرا

پیش‌نیاز: .NET SDK 10 و SQL Server.

```bash
# رشته اتصال در src/Fratak-Shop.Web/appsettings.json (کلید ConnectionDefault)
dotnet run --project src/Fratak-Shop.Web
```

در اولین اجرا Migration ها اعمال می‌شوند و دیکشنری استان/شهر و تنظیمات پیش‌فرض (منوها، کدهای تخفیف، قوانین باشگاه، قالب اعلان‌ها) ثبت می‌شود.
اگر `Shop:SeedDemoData = true` باشد و هنوز هیچ محصولی وجود نداشته باشد، داده نمایشی (دسته‌بندی، برند، محصول، بنر، مقاله و یک سفارش نمونه)
هم ساخته می‌شود. کاربر نمونه ۲٬۰۰۰٬۰۰۰ تومان موجودی کیف پول و ۱٬۵۰۰ امتیاز باشگاه دارد:

| نقش | موبایل | رمز عبور |
|-----|--------|----------|
| مشتری نمونه | `09120000000` | `123456` |

## تنظیمات

همه تنظیمات کسب‌وکار در **دیتابیس** نگهداری می‌شوند تا پنل ادمین بدون تغییر کد آن‌ها را مدیریت کند:

| جدول | محتوا |
|------|-------|
| `StoreSettings` | نام، شعار، لوگو، اطلاعات تماس، شبکه‌های اجتماعی، نقشه، حداقل سفارش، سقف ارسال رایگان، روزهای تعطیل، پرداخت در محل (روشن/خاموش + سقف)، زرین‌پال (مرچنت + Sandbox)، کیف پول (شارژ/برداشت/پرداخت + حدود)، امکان لغو توسط مشتری، مهلت پرداخت، سئوی پیش‌فرض، robots |
| `ShippingMethods` / `DeliveryTimeSlots` | روش‌های ارسال (پست، پیک، ارسال فوری، تحویل حضوری)، هزینه، استان، ارسال رایگان، پرداخت در محل، بازه‌های زمانی و ظرفیت |
| `ContentPages`, `FaqCategories`, `FaqItems` | صفحات ثابت و سوالات متداول (فعال/غیرفعال، نمایش در فوتر، سئو) |
| `HomeSections`, `SiteFeatures`, `TrustBadges` | بخش‌های صفحه اصلی (شامل «پیشنهاد برای شما» و «بازدیدهای اخیر»)، مزایای خرید، نمادهای اعتماد |
| `Menus`, `MenuItems` | منوی اصلی هدر، میانبرهای مگامنو و ستون‌های فوتر (عنوان، آدرس، آیکن، برچسب، فعال/غیرفعال، زمان‌بندی) |
| `Coupons`, `CouponTargets`, `CouponUsages` | کدهای تخفیف: درصدی/مبلغ ثابت/ارسال رایگان، سقف تخفیف، حداقل/حداکثر خرید، بازه زمانی، سقف کل و هر کاربر، محدودیت محصول/دسته/برند، اولین خرید، کاربر خاص |
| `LoyaltyRules`, `LoyaltyTiers`, `LoyaltyRewards`, `LoyaltyTransactions` | باشگاه مشتریان: امتیاز هر رفتار، سطح‌ها و ضریب، جوایز قابل خرید با امتیاز، دفتر امتیاز (با انقضا) |
| `NotificationTemplates`, `Notifications`, `NotificationReads` | قالب اعلان‌های خودکار، اعلان‌های کاربر و پیام‌های همگانی (بدون کاربر مشخص)، وضعیت خوانده‌شدن |
| `ProductFilterAttributes` | مشخصات فنی قابل فیلتر (سراسری یا برای یک دسته) |

پرچم‌های قابلیت‌ها هم در `StoreSettings` هستند: ورود با رمز/کد، ثبت‌نام با کد، تایید دومرحله‌ای، کد تخفیف، پیگیری مهمان، پیشنهاد محصول،
باشگاه مشتریان و کد معرف، نوار اطلاعیه، PWA (نام کوتاه، رنگ تم) و اطلاعات فروشنده روی فاکتور.

در `appsettings.json` فقط تنظیمات استقرار باقی مانده است:

| کلید | توضیح |
|------|-------|
| `Shop:SeedDemoData` | `true`: اگر هیچ محصولی در دیتابیس نباشد، کاتالوگ نمایشی و کاربر نمونه ساخته می‌شود (یک‌بار؛ داده موجود را تغییر نمی‌دهد). روی سرور واقعی `false` بماند |
| `Jwt:SigningKey` | کلید امضای توکن (حداقل ۳۲ کاراکتر؛ **در Production حتماً از متغیر محیطی/Secret تنظیم شود**) |
| `Jwt:AccessTokenMinutes`, `Jwt:RefreshTokenDays`, `Jwt:SessionRefreshTokenHours` | عمر توکن‌ها |
| `Security:BehindProxy`, `Security:KnownProxies` | `true` فقط وقتی برنامه پشت Nginx/IIS/Cloudflare است: هدرهای `X-Forwarded-For/Proto` فقط از آدرس‌های `KnownProxies` پذیرفته می‌شوند تا IP واقعی کاربر (برای محدودیت درخواست و نشست‌ها) و https بودن درخواست (لینک‌های مطلق، کوکی Secure، بازگشت زرین‌پال) درست تشخیص داده شود. بدون پراکسی `false` بماند تا کسی نتواند با هدر جعلی IP خود را عوض کند |

## احراز هویت

* مرورگر: Access Token (JWT، ۱۰ دقیقه) و Refresh Token (چرخشی، تشخیص استفاده مجدد) در کوکی‌های HttpOnly؛ تمدید خودکار و بی‌صدا.
* API / اپ موبایل: `POST /api/auth/token` ، `POST /api/auth/refresh` ، `POST /api/auth/revoke` ، `GET /api/auth/me` با هدر `Authorization: Bearer`.
* تغییر رمز یا «خروج از همه دستگاه‌ها» همه توکن‌ها را فوراً باطل می‌کند.

## پرداخت (زرین‌پال)

پرداخت سفارش و شارژ کیف پول به درگاه زرین‌پال (API v4) هدایت می‌شود. حالت آزمایشی با `ZarinPalSandbox = true` در `StoreSettings` فعال است
(مرچنت آزمایشی پیش‌فرض ثبت شده). برای Production مرچنت واقعی را ثبت و Sandbox را خاموش کنید. تایید پرداخت فقط سمت سرور و یک‌بار انجام می‌شود؛
پرداخت دیرهنگام یا تکراری به کیف پول برگشت داده می‌شود.

## نقاط توسعه

* **PWA:** `/sw.js` فقط فایل‌های ثابت (css/js/فونت) را کش می‌کند؛ صفحات HTML و درخواست‌های POST هرگز کش نمی‌شوند و در حالت آفلاین `/offline.html` نمایش داده می‌شود. با خاموش کردن `IsPwaEnabled` سرویس‌ورکر نصب‌شده خودکار حذف می‌شود.
* **کارهای زمان‌بندی‌شده:** هر ۵ دقیقه لغو سفارش‌های پرداخت‌نشده و پاک‌سازی توکن‌ها؛ هر ساعت هدیه تولد و انقضای امتیازها (`OrderMaintenanceService`).
* **پیامک:** `ISmsSender` — پیاده‌سازی فعلی پیامک را در لاگ می‌نویسد (و در Development کد تایید روی صفحه نمایش داده می‌شود)؛ برای Production یک ارائه‌دهنده (کاوه‌نگار، SMS.ir، ...) ثبت کنید.
* **تصاویر:** نام فایل‌های آپلودی از مسیر `/uploads/{products|categories|blogs|banners|brands}/` خوانده می‌شود (`Helpers/ImageHelper`).

## استایل (Tailwind CSS)

فایل `wwwroot/assets/css/output.css` از روی کلاس‌های استفاده‌شده در صفحات ساخته می‌شود:

```bash
cd src/Fratak-Shop.Web
npm install
npm run build:css     # یا npm run watch:css هنگام توسعه
```

## Migration

```bash
dotnet ef migrations add <Name> --project src/Fratak-Shop.Data --startup-project src/Fratak-Shop.Data
```

(`FratakShopDbContextFactory` رشته اتصال طراحی را از متغیر محیطی `FRATAK_SHOP_CONNECTION` می‌خواند.)

## CI

* `Build` — بیلد کامل Solution.
* `Verify` — بیلد هر پروژه با گزارش کامل خطاها، و اجرای برنامه روی SQL Server واقعی همراه با **تست دود سرتاسری**
  (`.github/scripts/smoke-test.sh`): همه صفحات عمومی، ورود، سبد خرید، ثبت سفارش پرداخت در محل، پرداخت اینترنتی با درگاه آزمایشی،
  ثبت دیدگاه، علاقه‌مندی، فرم تماس و ثبت‌نام.
